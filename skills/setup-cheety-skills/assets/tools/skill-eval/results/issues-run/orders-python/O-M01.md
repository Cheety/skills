# Teilstornierung mit Buchungsprotokoll

## Problem

Stornierungen sind heute nur ganz oder gar nicht moeglich. Bei Teilruecksendungen legt die Buchhaltung einen Gegenauftrag an, dessen reference zum Original nur im Kommentarfeld steht. Der Monatsabschluss braucht dafuer jedes Mal manuelle Zuordnung.

## Akzeptanzkriterien

- [ ] Ein Auftrag im Zustand bezahlt kann teilweise storniert werden
- [ ] Die sum aller Teilstornierungen uebersteigt nie den Auftragsbetrag
- [ ] Eine vollstaendige Teilstornierung setzt den Auftrag auf storniert
- [ ] Jede Teilstornierung erzeugt genau einen Buchungssatz mit reference zum Auftrag
- [ ] Buchungssaetze sind immutable
- [ ] Der Stornierungs-Handler verarbeitet dieselbe Ereignis-identifier nur einmal
- [ ] Eine Stornierung aus einem unzulaessigen Zustand hinterlaesst keinen Buchungssatz
- [ ] Die offene Restsumme ist jederzeit abfragbar

## Nicht-Ziele

- Keine Erstattung an den Zahlungsdienst — nur die fachliche Erfassung
- Keine Stornogebuehren
- Keine Konfigurierbarkeit der Betragsgrenzen
- Keine Aenderung bestehender Zustandsuebergaenge ausser dem neuen teilstorniert
- Keine neue Abhaengigkeit
