# Zahlungs-Handler meldet Doppelzustellung getrennt

## Problem

Der Handler liefert heute nur True oder False. Der Aufrufer kann nicht unterscheiden, ob eine Zustellung new, duplicate oder ungueltig war.

## Akzeptanzkriterien

- [ ] Eine erste Zustellung meldet new
- [ ] Eine wiederholte Zustellung derselben Ereignis-identifier meldet duplicate
- [ ] Eine leere Ereignis-identifier wird abgelehnt

## Nicht-Ziele

- Keine Persistenz der verarbeiteten Kennungen
- Keine Aenderung der Aufrufsignatur ausser dem Rueckgabewert

## Kontext

Betroffen: `src/jobs/payment_received.py`. Prinzip: `IDEMPOTENCY`.
