# Rabattberechnung nutzt die geprueften Posten

## Problem

totalWithDiscountCents ruft totalCents auf, verlaesst sich aber nicht sichtbar auf dessen Pruefungen. Bei einer spaeteren Umstellung koennte die Pruefung unbemerkt entfallen.

## Akzeptanzkriterien

- [ ] Ein Posten mit negativer Menge wird auch bei Rabattberechnung abgelehnt
- [ ] Die Rabattgrenzen bleiben unveraendert
- [ ] Ein Test haelt die Kopplung fest

## Nicht-Ziele

- Keine Duplizierung der Pruefungen
- Keine Aenderung der Rundung

## Kontext

Betroffen: `app/Support/Rechnungen.php`, `totalWithDiscountCents()`. Regressionsschutz fuer R-B01.
